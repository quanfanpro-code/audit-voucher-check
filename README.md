# 🧾 会计凭证检查与抽凭底稿

这是一套供人工智能助手使用的抽凭工作方法，适用于审计、财务尽调中的凭证检查，也可以用来复核已有底稿、纠正不恰当的结论。

你提供序时账、凭证附件和检查范围，助手按完整原始凭证号逐张检查。**每检查完一张，就把实际看了什么、如何比较、发现什么、怎样下结论写进 Excel 并保存。** 最终交付的是可以回查、可以复核的抽凭底稿。

技能名称是 audit-voucher-check。本仓库包含执行规则、判断边界、计划模板和空白 Excel 底稿。使用时需要能够读取本地资料、使用技能并编辑 Excel 的人工智能工具；仅下载这些文件不会自行开始检查。

## 🚀 第一次使用，从这里开始

### 1. 把技能放到工具能找到的位置

在 GitHub 仓库页面下载完整压缩包并解压，保留其中的文件和子文件夹。将技能文件夹命名为 audit-voucher-check，放入你所用工具指定的技能目录；如果工具提供“导入技能”或选择技能目录的功能，按该工具的说明导入。

打开 audit-voucher-check 文件夹，应该能直接看到 SKILL.md 和本说明，还能看到模板、参考规则等子文件夹。**不要只下载 SKILL.md，也不要只复制 Excel 模板。** 执行规则会引用其他文件，缺少它们可能导致判断或底稿填写不完整。

如果解压后多套了一层文件夹，应选择直接包含 SKILL.md 的那一层作为技能文件夹。不同工具的安装位置可能不同，使用自己工具的设置即可，不需要沿用作者的电脑目录。

### 2. 准备好检查资料

建议把同一项目的资料放在一个清楚可辨的项目目录中，并向助手提供以下内容：

| 准备什么 | 怎么说明更清楚 |
| --- | --- |
| 检查主体和期间 | 哪家公司、哪个账套、检查哪段期间 |
| 序时账或记账凭证 | 指定要读取的文件；有记账凭证影像时一并提供 |
| 凭证附件 | 指定附件所在文件夹，保留原文件名及原有对应关系 |
| 完整凭证号 | 按年度、月份、原始凭证字及号码列明；不同主体的同号凭证分开 |
| 检查要求 | 是首次检查、继续未完成工作，还是复核已有结论 |
| 已有计划和底稿 | 有已批准计划或已确认表式时直接提供，避免重新设计 |
| 输出位置 | 希望检查底稿保存在哪里；未指定时，在本项目资料目录中另建成果子目录 |

凭证号以原资料为准，前导零也保留。例如原号为“2026年03月记0027号”，就使用这个完整号码。不会另编“抽凭032”来代替原号。

你还没有确定检查哪些凭证时，可以先让助手拟定选取方案。指定检查、按判断选取和随机抽样会分别记录实际方法；已指定的凭证不会被擅自换成另一批。

### 3. 发送一句清楚的请求

下面的请求可以直接复制，再附上本次文件或告诉助手资料位置。

**先看计划，再决定是否开始：**

> 请使用 audit-voucher-check 技能，根据我提供的序时账、凭证附件及完整凭证号清单，先写详细检查计划。计划用简单的 Markdown 文档，写清范围、检查步骤、判断标准和底稿交付方式。我同意后再开始逐张检查。

**已有计划，直接执行：**

> 请使用 audit-voucher-check 技能，按已经确认的计划和凭证清单执行。每完成一张就保存检查过程、证据位置和当前结论，交付已填写的 Excel 抽凭底稿。总表第一列归纳本张凭证后附的附件，每张明细页保留返回总表的链接。

**以现有资料完成检查：**

> 请使用 audit-voucher-check 技能，仅凭我已经提供的资料完成能够实施的检查。逐张给出有事实依据的判断；确实不能判断的，只说明具体哪项不能判断、已经做过什么以及影响，不把所有凭证都列为待补资料。

**重新复核旧结论：**

> 请使用 audit-voucher-check 技能，以已有底稿记录的事实和证据为基础，重新复核每张凭证的结论。必要时可以定点查看原始资料。保留修改原因和历史记录，并同步更新单项结果、整张结论、总表及事项跟进。

**中断后继续：**

> 请继续这份抽凭底稿，从上次可靠保存的位置接着做。先核对资料是否变化，说明最后完成和下一张的完整凭证号，复用已有检查记录。

## 🧭 收到任务后，会怎样执行

### 第一步：确认范围和已有决定

助手先看完整对话、指定资料和已有计划，确认主体、期间、凭证范围、资料位置及交付要求。已经说明或批准的内容直接沿用，不反复要求确认。

如果你只要求计划，或者明确要求先审批，就先交计划，等待同意后实施。你已授权检查的，就在授权范围内连续完成。只有确实影响结果、又无法从现有资料查清的关键歧义，才集中向你说明。

### 第二步：把账簿和附件对应起来

助手建立凭证与资料的对应关系，识别同一凭证跨多个文件、同一票据存在多个副本等情况。会记录文件、页码或表格位置，方便复核人员回查。

资料有可读取文字时直接使用；遇到扫描页、金额识别不清或文字与图片矛盾时，再查看相关原图。重复文件可复用已经核实的内容，涉及不同凭证的入账、分摊或付款关系仍分别分析。

原始序时账和附件保持不变。项目底稿使用模板副本；已有确认表式时沿用，并补足必要字段。

### 第三步：先弄清这张分录在做什么

同样是支付一笔钱，可能是预付款、报销、归还借款、结算尾款，也可能是支付以前已经计提的费用。助手先记录完整分录和业务阶段，再判断应当比较哪些证据。

检查金额会说明口径，不把借方和贷方相加当成业务金额。如果序时账带有“对方科目”，会先确认是否拆分或重复展开，避免误加总。

### 第四步：按业务实际做五项检查

| 检查项 | 实际检查什么 |
| --- | --- |
| 原始凭证是否齐全 | 现有资料能否支持这笔分录的关键业务事实和金额；如认为不齐，具体缺少哪项必要依据，已有替代资料为什么不足 |
| 记账凭证与原始凭证是否相符 | 对同一事项比较主体、内容、数量、金额等，写出账载值和原始资料值，并解释税额、预付、退款或尾款关系 |
| 账务处理是否正确 | 按实际业务和适用依据检查确认、分类、计量、税务处理及冲销 |
| 是否记录于恰当的会计期间 | 比较应确认的业务时点或服务期间与入账期间，并考虑前期计提、预付和后续结算 |
| 回款单位与销售客户名称是否一致 | 对销售回款比较实际汇款人与销售客户；存在代付或平台结算时进一步分析关系 |

这五项会先判断是否适用。例如普通采购付款通常不适用“销售回款户名检查”，会写清原因。业务需要时可以追加审批、重复入账、资产状态等检查，并明确对象和依据。

### 第五步：把实际比较过程写进底稿

一项检查应当能看清：检查什么、依据什么、账上是什么、附件是什么、双方在哪里、做了什么核对或计算，以及结果如何。

不能只写“已核对，未见异常”。金额有组成关系，就记录组成及计算；资料只能证明某一部分，也把证明范围说清。没有实际做过的查验、访谈、盘点等，不会写成已经实施。

### 第六步：完成一张，保存一张

填写完本张明细后，同步更新总表和五项汇总，检查凭证号、附件摘要、结果及链接，再保存并回读。进度按实际保存完成的凭证张数计算，读取了多少文件不能代替检查完成数量。

助手会记下最后完成和下一张的完整凭证号。需要继续时，从这个保存点衔接。

## 📒 交付的 Excel 怎么看

空白模板包含以下五类工作表。正式底稿会为每张凭证建立独立明细页，因此工作表数量通常多于五张。

| 工作表 | 用途 |
| --- | --- |
| 逐张抽凭记录 | 一张凭证一行，查看附件摘要、完整凭证号、业务、金额、执行状态及当前结论，并进入该张明细 |
| 五项标准复核 | 集中查看每张凭证的五项结果、具体限制和当前结论 |
| 单张凭证底稿 | 保存本张分录、证据索引、逐项检查过程、事项、结论和修订记录；正式使用时按实际凭证分别建立明细页 |
| 事项跟进 | 汇总确实存在的问题、待解释差异和具体证据限制，记录处理状态 |
| 填写规则 | 查看字段口径和项目验收记录 |

### 📎 第一列：凭证附件

“逐张抽凭记录”的第一列是**凭证附件**，归纳这张凭证实际后附的资料，例如“设备采购合同、付款审批单、银行回单；设备发票两张”。数量只有在核实后才填写。

这一列帮助你快速知道附件是什么，详细文件位置仍保留在本张证据索引中。它不会只写“共五个文件”，也不会把另行查阅的制度、其他凭证附件或共用银行资料混称为本张后附资料。

同一张票的不同格式或合并副本会说明对应关系，不重复当作新增业务。附件摘要描述“有什么”；是否足以支持本张分录，由具体检查另行判断。

### 🔗 总表和单张明细可以来回跳转

在总表点击对应的明细链接，即可进入该张凭证检查记录。每张明细页顶部有**“返回逐张抽凭记录”**的链接按钮，已建立对应行时优先返回本张所在行。

即使链接暂时无法打开，底稿仍保留完整凭证号、文件位置和页码，便于直接查找。交付时会在最终保存位置检查关键链接和 Excel 实际打开情况。

### ✍️ 执行记录和人工签署分开

助手如实记录实际执行者和完成时间。项目组编制人、复核人以及复核日期，由实际完成相应工作的人据实填写，不自动代签。

“现有资料检查已完成”表示已经完成相应资料范围内的检查，不等于项目组复核已经完成，也不表示所有事项均已解决。

## ⚖️ 怎样判断问题，避免机械下结论

以下例子只说明判断方法，正式结论必须使用本项目实际事实。

**没有发票，不直接判原始凭证不齐。** 例如一笔预付款，现有合同、付款依据和实际支付资料可能已经支持其发生及金额。是否缺少必要原始凭证，要结合这笔分录所处阶段、判断目标和替代资料。

**银行付款缺少付款证明，应直接指出。** 如果账上记了银行付款，助手会查看对应银行回单、银行流水、收款方收款证明等资料，并分清哪些是本张后附、哪些是另处归档并关联本张、哪些只是审计时另查。已检查范围内没有本张的付款证明，就在该张完整凭证号下写“本张付款支持不齐”。另查流水若能对应这笔付款，还要单独写明“付款事实已核实”，不能把流水冒写成本张附件，也不能继续说付款无法判断。银行回单只是可用形式之一；付款支持不齐也不能直接说业务是假的或账上金额必然错。

**买入实物已经入账，却没有验收证明，也应直接指出。** 比如电脑已经列为固定资产，已检查附件只有发票，没有签收、入库或其他验收证明，就写“购入实物原始凭证不齐”，说明是哪张凭证和哪批实物。若只付了预付款，货物还未进入交付确认阶段，则不因暂时没有验收证明判问题。缺验收证明不能直接推断电脑没到货或账面金额错；交付日不明，只限定影响资产入账月份等具体判断。

**金额不同，要先确认比较的是同一事项。** 合同总额与首付款金额本来可能不同。应先看付款比例和结算安排，不能直接判为账证不符。确有不符时，要明确写出双方金额、差额和出处。

**审批偏离，与会计差错分别说明。** 账载金额与实际业务凭据一致，但未按适用制度办理审批的，可能是授权或流程问题；是否同时构成会计差错，需要另有依据。

**日期不同，不直接判跨期。** 发票日、付款日和业务发生日可能不同。已经在前期正确计提的费用，本期付款不应仅因付款晚于业务日期就判为费用迟记。

**户名不同，先记录事实，再判断关系。** 销售客户由第三方代付，或者通过平台结算，需要核对相应关系。名称不一致这个事实，本身不能直接证明收入虚假。

**“未能核实”只对应具体未决事项。** 要写明哪一点不能判断、已经查找或比较过哪些资料、还有什么影响。同张凭证的其他事项已经查明时，应保留这些结果；同项已有明确不符、另有问题未决时，也不能用“未能核实”把已证实结果盖掉。

总表中，发现具体问题的凭证整行标浅红色；确实有决定性事项未能判断且没有已查明问题的，整行标浅黄色。两种情况同时存在时标浅红色，结论文字同时说明问题和未决事项。每行都要写清事实，不能只靠颜色或“详见其他表”判断。

一张凭证写“发现明确问题”，应当同时有明确适用的比较标准，以及可靠证据证明实际情况与标准不一致。问题要说明性质、依据和涉及金额；仅有疑点或尚未解释的差异，保留其实际状态。

整张凭证会区分“所执行检查未发现具体问题”“尚有具体事项未能判断”“发现明确问题”等情况。明确问题和未决事项同时存在时，两者都保留。尚未实施的检查也会单独记录，不填成通过。

## 🔄 已有底稿，怎样重新下结论

先读已有底稿的事实、比较双方和证据位置，不把旧标签当成事实。例如原来写了“不齐”，需要重新看其依据究竟是什么。

已有记录足够时，直接据此复核；金额、对象、期间或比较关系不清楚时，再定点看相关原始资料及必要关联记录，不默认把所有凭证从头重查。

修改会保留原结论、新结论、修改理由、时间和执行者。随后同步更新本张各项当前结果、整张结论、逐张总表、五项汇总和事项状态，避免总表已经改正、明细仍留着旧结论。

## ⏱️ 如何控制速度和中断续作

一次建立账簿及附件索引，后续复用。重复附件已可靠读取的内容继续使用；只有具体疑点影响判断时才追加查看。

每张凭证都要记录和保存，但不用每张都重复检查整个工作簿、重新排版或重新识别全部图片。首张确认保存和链接可用后，按相同方式继续；表式变化时再针对变化检查。

续作时先确认资料有没有变化，再从已经保存的进度继续。源文件变动会影响原判断时，明确需要重新检查的对象及原因。

在现有资料范围内能够判断的，应当完成判断；确实需要新事实的事项，具体保留限制。不能为了提速省略关键比较，也不能用泛化的补件清单代替已有资料分析。

## ❓ 常见问题

### 没有记账凭证图片，只有序时账，还能做吗？

可以根据可靠的序时账和附件实施有依据的核对，并注明“以序时账记录核对附件”。没有见过原凭证票面，就不声称已经核对票面签章、附件张数等内容。

### 扫描件或者压缩包可以提供吗？

可以提供，助手会按本地工具能够读取的方式处理，并登记实际读取范围。扫描资料中关键内容看不清时，会限定说明受影响事项；压缩包及内部文件会对应登记，注意与已展开资料是否重复。

### 会自动查验发票真伪吗？

只有实际使用了可用查验渠道并取得结果，才会记录已查验。仅看见发票图片，或业务系统显示“查验失败”，都不能直接据此认定真票或假票。

### 为什么一张凭证可能既有问题，也有不能判断的事项？

因为不同检查可能依赖不同事实。例如某项差额已经查实，另一项期间依据仍不清楚。底稿同时保留两者，方便复核人员知道哪些已经确定、哪些仍有限制。

### 是否会把所有凭证都列成待补资料？

不会按每张凭证预设待补资料清单。只有确实存在的具体事项才进入跟进表，并说明现有证据、已做检查和未决内容。用户限定仅使用现有资料时，在该范围内完成可以实施的判断。

### 能根据这批指定凭证评价全部账务吗？

不能直接推到全部凭证。底稿会写清实际检查范围、选取方式和限制；为解释某张凭证查阅了关联分录，也不表示对那些关联凭证实施了全部检查。

### 会修改账簿、替企业调账或自动联系对方吗？

原始账簿和附件保持不变。发现问题可以记录有依据的建议；改变企业账务、向外发送资料或提出补件请求，须有相应授权。

### 文件保存成功，就算交付完成了吗？

还需核对指定凭证是否齐全对应、当前统计与明细是否一致、关键长文字是否可读、链接是否可用，并确认 Excel 实际打开情况。如果某项检查受环境限制没有完成，会如实说明。

### 📚 技能怎样使用规范性文件

[规范性文件索引](references/规范性文件/索引.md)列出已核对版本、来源、完整 Markdown 正文和下载保存的原始文件。使用时，助手先看索引，再读与本张凭证有关的条文，最后回到这张凭证的账簿和附件查事实。底稿要写清“依据哪份文件的哪一条、凭证资料显示什么、两者如何比较”，不能只写“违反规定”。

资料夹目前收录四份实际引用过的文件：《会计基础工作规范》、审计工作底稿准则、审计证据准则和审计抽样准则。前一份帮助判断原始凭证及记账凭证的要求；中间两份帮助记录检查过程并衡量证据；最后一份只在真正开展审计抽样时使用。指定检查若干张凭证，不等于可以用这些凭证推断全部账务。

例如，账上记录银行付款，附件里没有银行回单时，助手还要查银行流水、收款证明等现有资料。另查流水能证实付款，不自动补成“本张后附附件”；本张付款支持是否齐全与付款事实能否核实要分别写。购入实物并入账时，还要按《会计基础工作规范》的要求看有无验收证明，并分清预付款尚未到交付阶段的情形。

Markdown 方便查找和引用，发现文字有疑问时以同文件夹保存的原始文件为准。旧版征求意见稿没有收录。资料夹没有把整套企业会计准则混装进去；遇到具体确认、计量或税务问题，助手须先确定真正适用的有效条文，再用于该笔业务。规范文件的原文属于各自发布机构，仓库许可不改变其权利归属。

仓库还附有模板验证工具和独立复核记录。日常使用者不需要编写或运行代码来阅读本说明；具体文件读取和底稿处理由具备相应能力的助手完成。模板已在 Windows 桌面 Excel 环境中验证，其他工具能否完整保留链接、下拉选项和公式，需要按实际环境检查。

### 2026年9月24日：达尔文评估与抽凭判断优化

1. **设计检查情景。** 用三笔虚构情景检查规则：银行流水能证实付款但未归入本张凭证；设备入账却没有验收证明；只复核旧底稿中被标为“无法判断”的记录。[测试情景](test-prompts.json)保存在仓库，均不含客户资料。
2. **记录改前表现。** 第一名独立评审按达尔文九个维度给改前技能打了80.6分，只用于定位短板，不当作审计质量证明。未使用技能的回答在设备情景主要停在“无法判断”；使用改前技能已能指出验收支持不齐，但在付款情景中，另查流水与本张后附凭据的关系仍不够明确。
3. **定位和修正问题。** 现在先分清本张后附、另处归档且关联本张、审计时另查三类资料；付款事实和本张原始凭证齐全性分别下结论。复核旧底稿时，先筛出用户指定记录；只有附件名称、没有实际比较内容的，不批量改判。只拟计划时不再预先读完执行阶段的全部参考资料；用户要求先批准计划时，批准点明确标出，已有批准不重复询问。
4. **复查模板测试。** 发现原校验脚本只是解析链接公式并定位目标页签，没有真正点击链接，旧复核记录对此说得过满；现已更正。另补测“两个账套使用同一完整凭证号”的情形。桌面 Excel 的25项功能检查通过，测试前后空白模板校验值一致。最终项目底稿仍须实际点击正反向链接，不能拿脚本定位结果代替点击验收。
5. **比较改前与改后。** 三名独立评审用相同的三个情景逐对比较，三票均认为改后更好，其中两票认为差异明显、一票认为提升较小。设备情景两版表现相同；主要提升在付款证据归属和定点重判。比较基于虚构情景和规则文本，未重新检查真实项目的凭证，也不代表项目组复核签署。

**补做同尺度评分：** 第一名评审按原九维标准重评，改前 **80.6分**、改后 **82.4分**，提高 **1.8分**。其中“失败情况如何处理”由8分升至9分，“计划批准点是否清楚”由5分升至6分；另外七维保持原分，包含“实际执行表现”7分不变。另两名评审在各自同一尺度下分别给出 **79.4→82.9分**、**82.3→87.9分**。不同评审打分差别较大，不能把其中最高分或平均差值当作技能的客观质量。是否保留本次改动，依据的是三人对同一情景、同一版本对照的三票判断。

**验证边界：** 三个情景均为虚构资料下的规则推演，没有让新旧两版各自完成真实凭证的整套抽凭底稿。按达尔文技能对“干跑”比例的要求，这组绝对分数须标记为**评估不充分**，不能据此宣称实际抽凭质量已验收。25项桌面 Excel 检查只验证模板结构和引用；其中链接目标可定位不等于实际点击成功。后续在真实项目使用时，仍要检查逐张事实、结论和链接。
