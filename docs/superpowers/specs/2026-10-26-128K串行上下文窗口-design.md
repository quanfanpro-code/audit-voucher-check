# audit-voucher-check：128K 串行上下文窗口设计

日期：2026-10-26  
状态：按用户“自主推进后续流程、实际编码前停止”的授权定稿  
需求依据：`docs/requirements/2026-10-26-128K串行上下文窗口-requirement.md`

## 1. 设计目标与硬边界

新增只负责上下文调度的外壳。1M 保持现有流程；128K 以“一张凭证完整检查、保存并回读”为一个串行执行窗口。指定范围、资料页码、五项检查、专业判断、证据留痕、底稿格式和 Excel 验收均不缩减。

本次明确不改变 OCR，也不新增 OCR 模型或其他外部模型服务。

## 2. 方案比较

| 方案 | 成本与维护 | 等价性、风险与验证 | 可逆性 | 结论 |
|---|---|---|---|---|
| A：原技能内分流＋单张凭证串行窗口＋底稿断点 | 新增调度说明和辅助工具，复用原规则、模板和工作簿 | 每张证据与程序可逐项对照；需验证跨窗口没有把摘要误当已检查 | 停用新增入口即可恢复 | 推荐 |
| B：复制 128K 精简技能 | 两套判断边界和底稿规则需同步 | 容易漏检查、漏规范或改变结论口径 | 可回退但维护成本高 | 否决 |
| C：只在当前对话减少读取，不独立窗口 | 改动较少 | 已读图片、附件和判断过程仍累积 | 易回退 | 不满足硬门槛 |
| D：外部模型 API 或并行检查 | 需新配置和调用链 | 改变模型、并发和底稿写入安全 | 回退成本高 | 否决 |

## 3. 推荐架构

### 3.1 原技能内双入口

在 `SKILL.md` 前置元数据后增加一次询问：“本次使用 1M 还是 128K 上下文模型”。

- 1M：继续现有正文，不创建调度文件。
- 128K：读取 `references/128K串行上下文.md`，按单张凭证串行窗口执行。
- 新任务只问一次，续作窗口继承选择；没有活动凭证且用户明确要求时才变更模式，已保存底稿不重做。
- 不新建同名技能，不增加 OCR 问题。

### 3.2 三层职责

1. **业务真相**：指定凭证清单、原始资料、源文件版本、已保存工作簿和证据索引。调度摘要不是凭证事实或检查结论。
2. **主控窗口**：确认范围、逐个派发完整凭证号、核对保存回执和安排续作，不保留每张凭证的图片、附件正文和专业分析。
3. **执行窗口**：一次只检查一张凭证，完整执行原技能并写入同一主体工作簿，回读成功后只返回短回执。

执行窗口前台串行；上一张未保存并解除占用，下一张不得开始。任何主体都不得并行写工作簿。

## 4. 单张凭证任务包

每张任务包是调度清单，不是压缩后的业务答案，至少包含：

- 主体／账套、年度、月份、原始凭证字和号组成的完整凭证键；
- 当前工作簿路径、指定清单和已批准计划位置；
- 账簿索引、附件索引及源文件版本锚点；
- 原 `SKILL.md`、本张所需参考文件和规范性索引位置；
- 本张明细页、总表行和预期保存位置；
- 原任务要求的检查类型：首次检查、续作或旧结论复核。

执行窗口必须按原规则自行确定并读取本张实际需要的完整分录、附件、关联记录和适用条文。任务包不得用主控摘要替代原始证据，不得预先写“相符、正确、未发现异常”等结论。

同一票据的 PDF、OFD、扫描件仍按原规则避免重复计金额；一张凭证跨多个文件仍完整检查。单张所需资料无法完整装入一个窗口时停止，不把一张凭证拆成几个只看到部分证据的判断窗口。

## 5. 保存、回执与续作

### 5.1 原保存门禁不变

每个执行窗口必须：

1. 按原技能完成本张五项检查及必要追加程序。
2. 写入本张明细、总表行、问题及未决事项和修订历史（如适用）。
3. 保存并回读完整凭证号、事实、当前结论和双向链接。
4. 只有保存成功后才返回 `saved`；否则返回 `needs_retry` 或 `blocked`，不得开始下一张。

主控窗口只接收：完整凭证号、状态、工作簿路径、结果哈希、下一张技术状态和一句错误说明。不得要求执行窗口把整张底稿或全部证据复述回主对话。

### 5.2 辅助文件

在成果目录下的 `.上下文调度/` 辅助目录新增：

- `上下文调度状态.json`：模式、模型绑定、当前凭证占用、主控调度计数、工作簿路径及哈希。
- `上下文调度记录.jsonl`：开始、保存、恢复和主控轮换记录，只供程序核查。
- `单张凭证任务.json`：当前任务包及输入锚点，不包含主控推测的业务结论。

辅助目录不属于正式底稿，不参与专业判断。已保存 Excel 才是实际完成范围和结论的依据；恢复时仍须读取总表和本张明细核对，不得只信调度文件。

### 5.3 调度工具

新增 `scripts/串行上下文调度.ps1`，仅使用 Windows 自带 PowerShell 能力：

- `初始化`：仅在 128K 模式创建辅助状态。
- `开始`：登记完整凭证键、任务包及 SHA-256；已有活动凭证则拒绝。
- `完成`：在执行窗口已保存并回读后登记工作簿哈希并解除占用。
- `状态`：只输出当前占用、调度计数、工作簿锚点和少量路径。
- `交接`：生成新主控窗口所需的简短续作信息。
- `恢复`：显式记录异常恢复并解除陈旧占用；实际下一张仍由指定清单和已保存底稿确定。

主控窗口默认最多完成 20 张调度后轮换，宿主提前预警时立即轮换。该数字只限制主控历史，不改变指定凭证清单或单张检查内容。

## 6. 不同任务类型

### 6.1 拟计划

只需要计划时不启动逐张执行窗口，也不额外读取执行阶段资料。若用户选择 128K，计划仍按原模板完整形成；批准点不变。

### 6.2 首次检查或续作

按指定清单逐张串行。续作先核对源文件版本和已保存工作簿，再从下一张开始；不能凭调度计数判断完成。

### 6.3 复核旧结论

以需要复核的完整凭证键为窗口边界。优先读取旧底稿已有事实，具体歧义才定点回看原件；旧结论保留和同步更新规则不变。不得为了使用新窗口而默认全量重读或重新 OCR。

## 7. 数据流

```text
用户选择 1M
  └─ 原 SKILL → 原逐张检查流程，不创建辅助文件

用户选择 128K
  └─ 主控确认指定清单与版本 → 登记一张凭证
       → 前台启动一个执行窗口 → 完整读取本张所需资料
       → 原五项检查与判断 → 写入并回读同一工作簿 → 短回执
       → 主控核对保存状态并解除占用 → 下一张或主控轮换
```

## 8. 宿主适配与失败处理

| 场景 | 处理 |
|---|---|
| 宿主支持当前模型的独立 Agent | 前台串行，一张一个窗口 |
| 不能保证同一模型或窗口隔离 | 改用同模型手工独立对话；无法保证时停止 128K 路径 |
| 单张完整证据无法装入 | 停止并报告，不少看附件、不减少检查 |
| 工作簿保存或回读失败 | 保持占用，不开始下一张；恢复原保存点 |
| 凭证号、主体或源版本冲突 | 停止，按原规则查明，不默默改号或续跑 |
| 活动占用未解除 | 禁止下一张，显式恢复后核对底稿 |
| 执行窗口只形成 OCR、计划或字段提取 | 不得返回 saved，不视为完成抽凭 |
| 用户选择 1M | 不创建、不读取、不依赖辅助文件 |

## 9. 等价测试策略

1. **基线**：先核对现有 `test-prompts.json`、空白模板和 `scripts/校验底稿模板.ps1` 的适用状态；记录既有不一致或失败，不把旧问题算作新回归。
2. **路由与串行**：1M 不创建辅助文件；128K 活动凭证拒绝第二张；保存失败不能解除占用。
3. **任务包完整**：任务包包含完整凭证键、原资料索引和版本锚点，不包含预设专业结论；开始调度前后源文件哈希不变。
4. **保存门禁**：只有实际写入并回读后才允许 saved；OCR、计划或字段提取不能通过完成登记。
5. **断点**：在读取中、写完未回读、回读后未解除占用和主控轮换处恢复，不重写已完成凭证、不漏下一张。
6. **业务情景等价**：使用现有付款支持、设备验收和定点重判情景，两种路径均须满足原 `expected`，不减少事实、比较双方或限制。
7. **实际 128K 验收**：同一模型对代表性凭证完成整批串行检查，逐张比较证据范围、五项结果、结论、问题、修订和链接；存在未解释差异则不开放该路径。
8. **Excel 验收**：最终实际打开工作簿，检查张数、公式、格式、冻结、着色、长文本和双向链接；源模板与原始资料不被测试修改。

## 10. 迁移与回滚

- 不改写原空白模板，不把调度字段加入正式底稿。
- 已有底稿续作先按原规则核对版本和进度，辅助目录后建，不据此重排或重写历史结论。
- 回滚时停用新增入口和辅助脚本，原技能、模板和已保存底稿保持原样；不删除任何资料。
- 默认不执行 Git 提交、推送或分支清理。

## 12. 设计自审与检查点 2

- 没有把 OCR 纳入工程，也没有把减少附件或检查项当作优化。
- 单张窗口保存前不得开始下一张，符合串行和同一工作簿写入约束。
- 调度记录不能证明已检查，正式底稿仍是业务真相。
- 单张资料装不下时明确停止，不把部分证据拼成完整结论。
- 按用户自主推进授权，采用方案 A 连续进入实施计划编写；本轮不产生业务代码。
