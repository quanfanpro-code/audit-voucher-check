# 技能维护验收用例

本文件用于修改技能后的定向自检，不是每轮抽凭要额外执行的审计程序。情景是教学设定，不能用作真实项目证据。测试时要求实际给出分类及理由，不能靠搜索文档含有某几个词声称测试通过。

| 情景 | 必须得到的行为／结果 | 应能拦住的错误 |
| --- | --- | --- |
| 合同明确30%预付，实际支付与之相符，账挂预付，未开票交货 | 判断本阶段必要证据，无其他缺口时不能仅因无票判不齐 | 无票等于业务不存在 |
| 只见借款回单，直接列费用，现有资料核查后无支出及核销依据 | 点名费用发生及核销依据不足，说明回单所能证明的范围 | 为减少未知而判全部正常 |
| 账与实际银行付款同事项同口径相差200，无合理解释 | 列比较双方和差额，判断账证不符；进一步界定差错影响 | 一味用“无法判断”回避明确反证 |
| 账、票、付款612.00，最初审批600.00，无权限制度 | 账证金额相符；记录审批差12.00，不凭差额直接认定越权 | 把审批差归入账票不符 |
| 借款5000，报销4970.00，退款30.00，全部正确入账 | 勾稽后本项相符 | 把退款当报销差错 |
| 二月服务已计提，三月仅付款 | 不判费用跨期 | 只比较原单日期与记账日 |
| 合同六月二十五日前交货，六月十日确认，缺实际交付时点 | 只说明实际交付时点未明，不能认定六月十日未交付 | 将合同最晚日期当实际履约日期 |
| 以前月份实际服务、未计提、本月首次确认，证据已查清 | 记录归属月份差异，进一步区分报表期间影响 | 将所有日期差都说不重要或都说年报错报 |
| 设备按合同及验收确认全部成本，发票仅开一部分 | 资产计量与税额支持分别核查 | 部分开票自动等于全额资产错误 |
| 普通供应商付款 | 回款客户户名项不适用，写明原因 | 所有采购都“未核实销售客户” |
| 实际销售回款由客户母公司支付，代付依据已核实 | 保留户名不一致事实，解释关系，不自动判错账 | 名称差异等于虚假业务 |
| 底稿已有比较双方及退款解释，要求重做结论 | 直接使用已有事实；仅歧义处查原件；保留修订记录 | 全量重读／旧标签批量替换 |
| 同月同号两个账套 | 按主体和完整凭证号区分并链接各自明细 | 漏张、串号、自编抽凭号 |
| 一个附件格式暂无法读，其他资料足以判断金额分类 | 记录未读内容和仅受影响事项，其他结果照实判断 | 整张全列无法判断 |
| 发现明确错账，同时付款户名尚不清 | 当前结论保留明确问题和具体未能判断事项 | 一种状态覆盖另一种事实 |
| 旧流程结论是异常，事实只是不适用项目缺附件 | 保留历史、改当前结果，更新全部汇总及下拉 | 总表已改、明细或问题清单仍报旧异常 |
| 未实施发票官方查验 | 据实写未实施，不能声称通过或假票 | 虚构已执行程序 |
| 已存一张、中断后续作 | 回读已保存位置，从下一张或未完成步骤继续 | 重跑整批或补写虚假完成时间 |
| 同一账务处理项已查明数量多记，但进项抵扣条件尚不明 | 主结果保留不正确，明确列数量差错和税额限制并同步汇总 | 用一个未能核实抹去已确认错误 |
| 只有可靠完整序时账和业务附件，未提供记账凭证影像 | 如实按账载记录核对，票面特有事项单列未查看；不机械判业务原始凭证不齐 | 因缺票面影像否定所有账证比较 |
| 凭证注明附件4张，实际一份4页PDF包含这四份单据 | 核对内容覆盖后判断，不按4张减1文件算缺3张 | 混淆张数、文件数、页数 |
| 旧程序行写发现异常，但新增核对证明只是退款差额 | 原结果及理由进入历史，当前程序行、整张结论和汇总一起更正 | 只改汇总，细项仍报旧异常 |

## 模板功能验证

1. 空白凭证号时，总表和五项汇总不出现假凭证、零金额或“通过”。
2. 在测试副本输入完整凭证号、金额和五项结果，总表及汇总同步；清空凭证号后恢复空白。只填五项结果不得自动生成整张专业结论。
3. 在测试副本复制为两个不同真实形态的凭证号，分别填写不同结论及限制，调整汇总引用并验证无串号。
4. 同时存在明确问题和证据限制时，总表两项都可见；五项下拉允许各自的“不齐／不符／未能核实／不适用”。
5. 扩充分录或证据区后，后续栏目和公式位置正确；插行后的当前结论不能落到历史栏。
6. 最终文件能在 Microsoft Excel 实际打开；按正常缩放检查所有工作表，完整范围覆盖合并单元格的预览用于检查长文本，不能把被裁掉的合并区误判为乱码。
7. 重命名明细页后，检查 HYPERLINK 的文字目标确已改成新页，不能只检查普通公式已更新；实际验证导航到正确凭证。
8. 从有完整业务、证据、事项和历史的明细复制新页，按清理清单复位，验证新页及汇总不残留前张事实或结论。优先采用干净模板页。

技术校验只能证明文件结构与引用，不能证明未来执行者的职业判断必然正确。维护记录应区分同一执行者的情景走查、工具运行验证和实际项目试用；未做独立盲测不能写已通过独立复核。
