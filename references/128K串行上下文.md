# 128K 串行上下文窗口运行说明

本说明只规定上下文调度如何交接，不替代任何业务规则。五项检查、适用性判断、
问题门槛、底稿填写、规范条文和 Excel 验收仍以 `SKILL.md` 原正文和
`references/判断边界与实例.md` 为准；执行窗口必须先读原技能和适用规范。

## 1. 模式选择与续作

- 每次新任务只询问一次："本次使用 1M 还是 128K 上下文模型？"
- 选择 1M：按 `SKILL.md` 原正文执行，不创建、不读取任何调度文件，业务行为保持现状。
- 选择 128K：按本说明执行；续作窗口从调度状态继承模式选择，不重复询问。
- 没有活动窗口且用户明确要求变更模式时才允许变更；不得重置已保存的底稿和证据索引。

## 2. 单张完整检查为窗口边界

- 一个执行窗口一次只处理一张凭证的完整检查：读取该张按原规则需要的全部账簿分录、后附附件、关联记录和适用条文，执行同样的五项检查及必要追加程序，写入并保存同一主体工作簿。
- 单张任务包（JSON）固定包含字段：`voucher_key`（完整凭证键）、`workbook_path`、`approved_scope`、`source_indexes`、`source_versions`、`required_references`、`check_type`、`output_location`。任务包不得预设结论——包内不出现专业结论字段，结论只能由执行窗口依据证据作出。
- 调度与摘要只是线索：执行窗口只能声明自己实际读取和实际执行的程序，不得预设结论，也不得把主控摘要当作已执行检查。
- 单张凭证的完整证据无法装入一个执行窗口时，明确停止并报告，不得少看附件、减少检查或拆成只看到部分证据的判断窗口。

## 3. 串行与保存门禁

- 执行窗口必须前台运行、串行调度：同一时刻最多检查一张凭证；上一张保存并回读成功、调度占用解除后，才能开始下一张。
- 执行窗口必须使用当前对话正在使用的同一个模型；宿主不能保证同一模型时，不启动自动 Agent，改用同模型手工独立对话交接；无法隔离窗口时停止 128K 路径。
- 完成登记必须显式提供 `-SavedAndReadBack` 开关：它只证明执行窗口声明"已保存并回读"，调度脚本不因此变成专业验收工具；每张仍须按原规则实际保存并回读完整凭证号、事实、结论和双向链接。
- 主控窗口默认完成 20 次调度后必须轮换（`CONTROLLER_DISPATCH_LIMIT = 20`）；宿主提前发出上下文预警时立即轮换。新主控读取 `交接` 输出、指定清单和已保存工作簿续作，不读取旧聊天；调度计数不当作实际完成张数。

## 4. 短回执

- 执行窗口只返回：`voucher_key`、`status`（saved / needs_retry / blocked）、`workbook_path`、`workbook_sha256`、`next_action`、`message`。不得返回整份证据文字或专业推理正文。
- 主控收到回执后核对工作簿已保存（文件存在、哈希登记），再调用 `完成` 解除占用；任何主体不得并行写同一工作簿，不同主体使用各自工作簿，不得混簿。

## 5. 调度命令

`scripts/串行上下文调度.ps1` 只使用 Windows 自带 PowerShell，子命令：`初始化 / 开始 / 完成 / 状态 / 交接 / 恢复`。

```powershell
$PY = 'C:\BaiduSyncdisk\workbuddy skills\audit-voucher-check\scripts\串行上下文调度.ps1'
powershell -NoProfile -ExecutionPolicy Bypass -File $PY -Action 初始化 -Root <工作目录> -Mode 128K -ModelBinding <当前模型> -BackupRoot <备份目录>
powershell -NoProfile -ExecutionPolicy Bypass -File $PY -Action 开始 -Root <工作目录> -TaskId <完整凭证键> -TaskPacket <单张任务包.json> -WindowId <窗口标识> -BackupRoot <备份目录>
powershell -NoProfile -ExecutionPolicy Bypass -File $PY -Action 完成 -Root <工作目录> -TaskId <完整凭证键> -ResultWorkbook <工作簿路径> -SavedAndReadBack -BackupRoot <备份目录>
powershell -NoProfile -ExecutionPolicy Bypass -File $PY -Action 状态 -Root <工作目录>
powershell -NoProfile -ExecutionPolicy Bypass -File $PY -Action 交接 -Root <工作目录>
powershell -NoProfile -ExecutionPolicy Bypass -File $PY -Action 恢复 -Root <工作目录> -TaskId <完整凭证键> -Reason <原因> -BackupRoot <备份目录>
```

- 调度辅助文件位于 `<工作目录>\.上下文调度\`，只用于调度，不是业务真相；指定清单、原始资料和已保存工作簿仍是唯一业务依据。
- 覆盖调度状态前脚本自动备份到 `-BackupRoot` 并做哈希校验。

## 6. 异常恢复与停止条件

- 异常中断后，经用户或主控明确确认，用 `恢复` 解除陈旧占用并留痕原因；恢复后仍须读取正式底稿和指定清单确定下一张，不能凭调度记录猜测完成。
- 出现以下情况立即停止并报告，不得降级硬跑：单张完整证据装不下执行窗口；不能保证执行窗口使用当前同一模型；无法隔离窗口；保存失败、凭证号冲突或资料版本变化；OCR 成功、字段提取或附件清单不得冒充完成抽凭——OCR 不在本工程范围内。
